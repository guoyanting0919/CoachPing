# 04: 教練端的結束／恢復介面

**What to build:** 學員清單分「進行中／已結束」兩個分頁，卡片點開可以結束合作，
已結束的卡片點開可以恢復。

互動沿用 `liff/coach/session-actions.tsx` 的原地 `Mode` 狀態機——點卡片展開 menu，
選動作後進確認畫面。不用 `window.confirm`：它裝不下「同時取消 N 堂課」的勾選框，
風格也跟課表操作不一致。

不要求打字輸入學員名字。這是可逆動作，不該把成本加在每次正常使用上。

`GET /api/coach/members` 一次回兩組（進行中 + 已結束），切分頁不再等 loading——
清單都很小，而且跟現有「一併撈出來省一次往返」的 `pendingInvites` 寫法一致。

## 實作紀錄

`GET /api/coach/members` 改成一次撈所有關係再分組，`ended` 那組附 `endedAt`；
`linkedCount`／`totalCount` 只算進行中。額外多一次 `groupBy` 算每位學員未來的課數
（確認畫面要講的那個 N），範圍限定這位教練、`scheduled`、`startAt >= now`。

排課畫面的 `member-picker` 吃的是同一支 API 的 `members`，已結束的自然不在裡面——
不需要改 `schedule-form`。

互動抽成 `member-actions.tsx`，跟 `session-actions` 同一個原地 `Mode` 狀態機。
勾選框只在未來有課時出現，並隨勾選狀態換說明文字（勾：他會收到一則取消通知／
沒勾：那 N 堂課會照原定時間進行）。未連結學員的版本直接說「他收不到通知，要你自己告訴他」。

結束完成後若該學員未連結且真的取消了課，不直接收合卡片，而是停在一則提示上要教練按
「知道了」——降級流程唯一的把手就是教練本人，一閃而過的 toast 擋不住他忘記。

分頁只在有已結束關係時才出現。多數教練永遠看不到那一排，不該為罕見狀態付版面。

**未驗證**：整段 UI 都沒在 LIFF 真機上走過（需要 `db:push` 之後才能跑）。
