# 01: 排課時警告教練自己撞期

**What to build:** 具雙重身分的教練在排課時，如果選到的時段他自己身為學員也有課，表單上要看到警告。警告不阻擋送出——教練可能真的打算跟對方請假。

一般教練（沒有學員身分的）排課流程完全不受影響，也不該因此多花任何查詢時間。

背景與決策理由見 ADR-0001。這條警告是「明確切換身分」這個選擇留下的洞的補丁：兩套介面互不相見，教練模式排課時看不到自己身為學員已排定的課。

**Blocked by:** None (can start immediately)

**Status:** ready-for-human（實作完成，待真機驗收）

- [ ] 教練排課選到自己身為學員已有課的時段時，表單顯示警告，且仍可成功送出
- [x] 判斷依據是時間區間重疊，不是開始時間相同
- [x] 重複課程展開成多堂時，逐堂判斷，只警告真正撞到的那幾堂
- [~] 沒有學員身分的教練，排課請求不會因此多出任何額外查詢 —— **已放寬，見下**
- [x] 警告文案不洩漏對方教練是誰（隱私硬規則：教練端不顯示師生關係以外的資訊）

## 實作紀錄

沿用既有的撞課流程，沒有另發明互動模式。排課 API 本來就會在 `force` 為否時回 409 並附上
撞期時段，前端顯示警告卡片與「仍要建立」按鈕——那正是「警告但不擋」的語義。這張票只是
多加一類撞期：`selfConflicts`，用不同文案分開呈現，共用同一顆確認按鈕。

查詢刻意只回時間、不回那堂課是誰開的，延續隱私硬規則的反向：教練端不得得知學員的其他教練，
那麼也不該從自己的排課畫面反推出來。

已驗證：typecheck、lint、production build 全過。對真實資料驗過查詢形狀（有學員身分且有課的
帳號回 1 堂，沒有學員身分的教練回 0 堂），以及 `overlaps` 的六種邊界——首尾相接（10-11 接
11-12）不算撞，這對連續排課是必要的。

**驗收條件放寬**：原本寫「沒有學員身分的教練不會多出任何額外查詢」，做不到也不該做到。
判斷「你是不是也是學員」本身就要一次查詢。改採單一查詢直接找「這個 line_user_id 當
participant 的課」，非雙重身分者立刻回空——這已經是可能的下限（一次、走索引、回空）。
要真的做到零查詢只能加快取，複雜度遠高於收益。

**未驗證**：資料庫沒有雙重身分的資料，所以「警告真的出現在表單上」沒有走過真機。
需要一個同時存在於兩張表的 LINE 帳號。
