# 03: 雙重身分版 Rich Menu 與模式切換

**What to build:** 具雙重身分的人在 LINE 裡拿到帶「切換」鍵的專屬選單，按一下就在教練模式與學員模式之間換邊。

兩張新選單只綁給雙重身分者。一般教練繼續拿現在的六格選單，一般學員繼續拿現在的四格選單——不讓絕大多數使用者為一個罕見功能付版面代價。教練版的切換鍵放在第二列（該列改為四格），上列三個最高頻的按鈕位置不動，切換時肌肉記憶不會錯位。

**模式狀態不進資料庫。** 切換走 LINE 原生的選單切換動作（客戶端瞬間完成），它會回送一個事件給我們；收到時把該使用者的選單綁定同步過去，於是「這個人現在在哪個模式」直接向 LINE 查詢即可。理由與取捨見 ADR-0001——這點很反直覺，動它之前先讀。

**這張票同時修掉一個現存缺陷**：已經是教練的人完成學員註冊時，目前會無條件被綁上學員選單，教練選單當場消失且沒有任何地方會綁回去。修好後他會停在學員模式的雙重身分選單——他剛完成學員註冊，下一步多半是看自己被排了哪些課，而切回教練只要按一下。

## 實作紀錄

已上傳到正式 LINE 帳號。向 LINE 反查驗證過：

```
alias  coach-mode  → coach_dual      alias  member-mode → member_dual
coach_dual    7 格  切換 → member-mode   member_dual   5 格  切換 → coach-mode
coach         6 格  無切換鍵             member        4 格  無切換鍵
unregistered  1 格
currentMenuRole：教練 YT → coach，學員 Jenny → member
```

一般 `coach`／`member` 兩張的格數與版面與改動前完全相同。

**建立順序不可調換**：選單先建（其中的 `richmenuswitch` 可以引用尚不存在的 alias），
alias 後建。反過來會失敗。這點查證過 LINE 文件，也由這次實際上傳印證。

`primaryRole` 現在對雙重身分者回 `coach_dual`，所以加好友、教練註冊兩條路自動走對。
`member_dual` 刻意不由 `primaryRole` 產生——它只在「剛完成學員註冊」與「主動按切換鍵」
兩個情境由呼叫端明確指定。

切換的 postback 處理有一道防禦：身分若在兩次切換之間變了（例如學員記錄被整筆刪除），
就綁回他真正該有的那張，而不是硬塞一個空的模式給他。

**未驗證**：整條切換路徑（按鍵 → 選單換邊 → webhook 同步綁定 → `currentMenuRole` 讀到
新模式）沒有真機走過，因為資料庫裡沒有雙重身分的人，沒有人會拿到 `*_dual` 選單。
這也是 04 的前提。
