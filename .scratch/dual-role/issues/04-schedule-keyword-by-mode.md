# 04: 打「課表」兩字依當下模式回覆

**What to build:** 雙重身分者直接在聊天室打「課表」，拿到的是他當下模式對應的那一份：教練模式回今天要教的課，學員模式回今天要上的課。

選單按鈕本來就沒有歧義（兩張選單的按鈕各自送出不同的指令），有歧義的只有直接打字這條路徑。

當下模式向 LINE 查詢該使用者目前綁定的選單即可得知，不需要新增任何資料庫欄位（見 ADR-0001）。

回覆一律使用回覆訊息而非推播——回覆免費且不佔推播額度，這是查課表走這條路徑的全部理由。

**Blocked by:** 03

**Status:** ready-for-human（實作完成，待真機驗收）

- [ ] 雙重身分者在教練模式打「課表」，回今天要教的課
- [ ] 同一人切到學員模式打「課表」，回今天要上的課
- [x] 其他既有關鍵字（今日課表、今天課表、今日）行為一致
- [x] 一般教練、一般學員打「課表」的行為完全不變
- [x] 向 LINE 查詢模式失敗時有合理退路，不是沉默失敗或回錯邊
- [x] 全程使用回覆訊息，不佔推播額度

## 實作紀錄

`currentSide` 決定這個人當下站在哪一邊：單一身分者就是他唯一的身分，不多打一次 LINE API；
雙重身分者才向 LINE 查目前綁著哪張選單。查不到時退回教練模式，與 `primaryRole` 給雙重身分者
的預設一致——兩處保持同一個答案，使用者才不會因為 LINE 暫時不可用就突然看到另一邊的資料。

**順帶修掉 03 引進的一個 regression**：03 把 `Role` 擴充成五種之後，雙重身分者的
`primaryRole` 會回 `coach_dual`，而 webhook 文字回覆那串三元判斷只認得 `coach`／`member`，
會全部落空讓他收到「請先點下方選單完成註冊」。改用 `currentSide`（只回三值）之後就對了。
這個 regression 從沒上線過——03 與 04 之間沒有部署。

**未驗證**：需要雙重身分的帳號才能走完整條路徑。
